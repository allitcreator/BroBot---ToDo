# Ритуал разбора дня — план

Статус: черновик 2026-10-26, до реализации. Прошёл критику `skeptic`,
подтверждённые возражения учтены.
Макеты и спецификация — `design/ritual.html` (концепция B, выбрана Александром).

## Цель

Бот дважды в день сам зовёт разобрать задачи, а разбор занимает 1–2 минуты:

- **Утро** (9:30): сводка в чат, если есть что решать. Кнопка открывает
  пошаговый разбор: Просрочено → Застряло → Входящие → План дня.
- **Вечер** (20:30): сводка, если на сегодня остались открытые задачи.
  Разбор: «Что успел?» → «Остальное на завтра» → «День закрыт».
- Между ритуалами — обычный экран «Сегодня» с плашкой «N во входящих».

## Не входит

- Недельный обзор (Александр: не нужен).
- Время выполнения задач: Graph хранит только дату.
- Всё про проекты: кнопки «В проект» в ритуале нет (Александр: проекты
  пока не продуманы). Вкладка «Проекты» остаётся как есть.
- Правка событий Google Calendar из мини-аппа: только показ.

## Определения

Все даты — в `config.USER_TIMEZONE` (Europe/Moscow), «сегодня» —
`config.local_today()`.

- **Просрочено** — открытая задача с датой раньше сегодня.
- **Входящие** — открытая задача без даты (как в `get_inbox_tasks`).
- **Застряло** — открытая задача, созданная (`createdDateTime`) не меньше
  N дней назад (N из настроек, по умолчанию 14), **без даты или с
  просроченной датой**. Задачи на сегодня и на будущее не застряли — они
  запланированы и видны в плане дня.
- **Пересечения:** в шаг «Застряло» попадают до 3 самых старых; эти
  задачи в тот же раз исключаются из «Просрочено» и «Входящих». Остальные
  застрявшие остаются в своих обычных шагах.
- «Через 2 недели» ставит дату +14: задача уходит из среза и вернётся в
  него, только если и после этого её не тронули и она просрочилась.
- **Норма дня** — медиана закрытых задач в день за 30 дней по дням с
  закрытиями (по аудиту — 5). Считается раз в сутки, кэш до полуночи.
  Если чтение упёрлось в `MAX_PAGES` (500 задач), предупреждение в лог.

## Этап 0 — до ритуала

Два дела, без которых ритуал размножит баги или упрётся в непроверенное:

1. **Перенос задачи со временем спрашивает время и двигает напоминания.**
   Времени у самой задачи нет: Graph хранит только дату (полночь UTC,
   проверено 2026-10-26, см. `HANDOFF-archive.md`). «Время задачи» — это
   напоминание бота (`reminders.fire_at`), напоминание MS To Do
   (`reminderDateTime`) и событие Google Calendar (`task_calendar_links`).
   Сейчас перенос не трогает ни одно из них — ни в чате, ни в мини-аппе,
   и они срабатывают в старый день.
   - Задача без напоминаний и события переносится как сейчас.
   - Задача с ними (значки 🔔/🗓): при переносе в мини-аппе поле времени,
     заполненное старым временем (начало события, иначе время
     напоминания). Можно поменять или снять время — тогда напоминания и
     событие удаляются.
   - На новое время переезжают: событие (длительность сохраняется),
     напоминание бота и MS To Do (с тем же отступом от начала события,
     что был; без события — ровно на новое время).
   - Массовый перенос в мини-аппе («Остальное на сегодня / на завтра»):
     поле времени только у задач с 🔔/🗓, одна кнопка подтверждает всё.
   - Команды чата `/today2tomorrow`, `/overdue2today` не спрашивают:
     напоминания и событие переезжают на новый день в то же время.
   - Новое: `google_calendar.update_event` (PATCH start/end), общая
     `task_ops.reschedule(task_id, day, time | None | KEEP)`; API
     `schedule` и `move` принимают `time` на задачу, `GET` задач отдаёт
     `time`.
   Сначала тесты: перенос с `time=16:00` двигает напоминание и событие;
   перенос без времени их удаляет; задача без них — только дата.
2. **Проверка параметра web_app-кнопки.** Команда `/ritual morning|evening`
   (только для `TELEGRAM_USER_ID`) присылает сводку немедленно, без записи
   в `ritual_runs`. На этапе 0 она шлёт кнопку на
   `MINIAPP_URL` + `ritual=test`, а мини-апп пишет полученный параметр в
   консоль. Так проверяем, что query доходит из inline web_app-кнопки.
   URL собирается через `urllib.parse`, чтобы не сломать `MINIAPP_URL`,
   если в нём уже есть `?`. Та же команда потом служит ручной проверкой
   сводок вместо подмены времени.

## Поведение бота

### Сводки

| | Утро | Вечер |
|---|---|---|
| Время по умолчанию | 9:30 | 20:30 |
| Когда шлём | просрочено + застряло + входящие > 0 | открытых на сегодня > 0 |
| Текст | «☀️ Доброе утро! Сегодня 4 задачи и 2 встречи. Ждут решения: 1 просрочена, 2 застряли, 3 во входящих» | «🌙 Закрываем день? Сделано 3 из 6. Осталось 3» |
| Кнопки | «Разобрать ↗» (web_app), «Позже» | «Закрыть день ↗» (web_app), «Не сегодня» |

- Каждую сводку можно выключить; время настраивается с шагом 30 мин.
- Выходные (сб, вс) — по умолчанию без сводок (подтверждено), флаг в
  настройках.
- Встречи в утренней сводке — из Google Calendar. Календарь недоступен —
  строка про встречи пропадает, сводка всё равно уходит.
- «Позже» — повтор через час, один раз; старое сообщение сводки удаляется.
  «Не сегодня» — молчим до завтра. После «Позже» и пройденного ритуала
  (`POST done`) повтор не приходит.
- «Сделано X из Y»: X — закрытые сегодня (любые), Y = X + открытые на
  сегодня.
- web_app-кнопка ведёт на `MINIAPP_URL` с `ritual=morning|evening` в query.
  `startapp` работает только для ссылок `t.me/<bot>/<app>`, у нас кнопка.

### Планировщик

- `_reminder_loop` раз в 30 с запускает `rituals.tick(bot, now)` отдельной
  задачей (`asyncio.create_task`) с `wait_for(…, 60)`: зависший Graph не
  задерживает обычные напоминания. Пока предыдущий `tick` не закончился,
  новый не стартует.
- Решение «слать или нет» — чистая функция
  `due_rituals(now, settings, runs) -> list[kind]` без сети, под тесты.
- Таблица `ritual_runs(kind, day, status, sent_at, snooze_at,
  message_id, done_at)`, `PRIMARY KEY (kind, day)`:
  1. `INSERT OR IGNORE … status='sending'`; 0 строк — уже шлём или
     отправили, выходим;
  2. подсчёт и отправка;
  3. успех — `status='sent'`, `message_id`; ошибка MS To Do или Telegram —
     запись удаляется, повтор не чаще раза в 5 мин.
  Дубль возможен, только если процесс упал между отправкой и `UPDATE`.
  Запись `sending` старше 10 минут после рестарта считается брошенной и
  удаляется.
- Окно опоздания: бот лежал в момент сводки — шлём после подъёма, но не
  позже чем через 2 часа после времени сводки. Позже — пропуск.
- Сеть трогаем только когда время сводки наступило, а записи за день нет.
- Время сводки, изменённое после её отправки, в тот же день повторную
  сводку не даёт — это ожидаемо; проверка — через `/ritual`.

### Настройки (БД)

Новые колонки в `settings` (миграция `ALTER TABLE`, как у
`research_enabled`):

| Колонка | По умолчанию |
|---|---|
| `morning_enabled` | 1 |
| `morning_time` | `09:30` |
| `evening_enabled` | 1 |
| `evening_time` | `20:30` |
| `stuck_days` | 14 (варианты 7 / 14 / 30) |
| `weekend_rituals` | 0 |

`GET/PATCH /api/settings` расширяется этими полями с валидацией
(время `HH:MM`, кратно 30 мин; `stuck_days` из списка).

## API

| Метод | Что отдаёт / делает |
|---|---|
| `GET /api/ritual/morning` | `{overdue[], stuck[], inbox[]}` одним `get_all_tasks()` |
| `GET /api/ritual/plan` | `{events[] \| null, today[], norm}`; задачи, связанные с событием (`get_task_ids_in_calendar`), показываются одной строкой — событием с отметкой задачи |
| `GET /api/ritual/evening` | `{today_open[], done_today, tomorrow[], tomorrow_events[] \| null, inbox_count}` |
| `POST /api/ritual/{kind}/done` | отметка `done_at` в `ritual_runs` |
| `POST /api/tasks/move` | новый вариант тела `{keys[], to}` (сегодня, завтра или дата), ответ «перенесено X из Y» |
| `GET /api/stats` | добавить сумму `completed_week` (сейчас только список `week`) |

- План дня — отдельный запрос в конце разбора, а не часть первого ответа:
  задачи, перенесённые на сегодня в шагах 1–3, должны в нём быть. Кэш
  задач сбрасывается при любой записи (`services/ms_todo.py:103`).
- События дня: новая `google_calendar.get_events_day(day)` (сейчас есть
  только `get_events_week` от текущего момента). Ошибка Google — `null`, и
  фронт пишет «календарь недоступен».
## Мини-апп

- `App` читает `ritual` из `location.search`. Есть — открывает экран
  ритуала поверх вкладок; закрытие ритуала — экран «Сегодня».
- **Утро**, `RitualMorning`: шаги из ответа API, пустые пропускаются,
  полоска прогресса по числу непустых шагов. Таймер «разобрано за …» —
  на клиенте.
  1. Просрочено — список, у каждой «Сегодня / Дата / Удалить», внизу
     главная кнопка «Остальное на сегодня» (`move` по оставшимся ключам).
  2. Застряло — по одной карточке: Сегодня / Через 2 недели / Удалить /
     Пропустить.
  3. Входящие — по одной карточке с заметкой (источник форварда):
     Сегодня / Дата / Удалить.
  4. План дня — `GET /api/ritual/plan`: встречи, задачи, строка про норму.
     «Начать день» → `POST done`, экран «Сегодня».
- **Вечер**, `RitualEvening`: шаг 1 — чекбоксы «Что успел?», закрытие
  пачкой по «Дальше», а не по тапу, чтобы можно было передумать; шаг 2 —
  оставшиеся с выбором дня (по умолчанию завтра), превью завтра;
  «Закрыть день» → переносы → экран итогов.
- **Сегодня** становится вкладкой по умолчанию. Плашка «N во входящих —
  Разобрать» открывает шаг «Входящие» отдельно.
- **Настройки** — раздел «Ритуалы» по макету.
- Ошибка посреди ритуала — как сейчас: откат карточки, текст ошибки,
  уже сделанное не теряется.

## Этапы

Тесты до кода, каждый этап — отдельный коммит. Выкатка разрешена
Александром для этой задачи; ручной приёмки нет — проверяем сами
(тесты, сквозной смоук на проде, логи). Выкатки помечены ниже.


0. **Перенос с выбором времени и `/ritual` с проверкой параметра.**
   Приёмка: `deploy/smoke_reschedule.py` на проде 12/12 (событие,
   напоминание бота и MS переехали; «без времени» снимает их).
   → **выкачено 2026-10-26** (`5b568b8`). Доход `?ritual=` из кнопки в
   Telegram живьём не проверен — по документации Telegram query
   сохраняется; подтвердим по логу nginx (`GET /?ritual=`) после первой
   сводки.
1. **Настройки ритуалов.** Миграция, storage, API, раздел «Ритуалы».
   Приёмка: значения переживают рестарт; неверное время — 400.
2. **Планировщик и сводки.** `services/rituals.py`, `ritual_runs`, кнопки
   «Позже / Не сегодня». Приёмка — тесты `due_rituals`: время, выходные,
   выключено, рестарт без дубля, сбой отправки с повтором, окно 2 часа,
   «Позже» один раз, нет повтора после `done`. Не выкатывается отдельно:
   без этапа 3 кнопка откроет обычный экран.
3. **Утренний ритуал.** Приёмка: кнопка из сводки
   открывает разбор; пустые шаги пропущены; задача не показана в двух
   шагах; задача, перенесённая на сегодня в шагах 1–3, видна в плане дня;
   задача с событием в календаре показана один раз. → **выкатка 1–3**.
4. **Вечернее закрытие.** Приёмка: «Сделано X из Y» в сводке и в
   мини-аппе совпадает; перенос с выбором дня двигает напоминания. →
   **выкатка**.
5. **Главный экран.** «Сегодня» по умолчанию, плашка входящих, кнопка
   меню переименована, вкладка «Входящие» остаётся. → **выкатка**.

## Проверки

- `venv/bin/python -m pytest tests -q`, `cd miniapp && npx vitest run`,
  `npx tsc --noEmit` — после каждого этапа.
- На проде после выкатки — сквозной смоук подписанными запросами к API
  изнутри контейнера (как `deploy/smoke_reschedule.py`), с уборкой за
  собой; логи бота без ошибок. Для сводок — смоук `tick` с подменой
  времени и отправкой в чат владельцу, запись в `ritual_runs` проверяется
  и удаляется.

## Риски

- Graph отвечает 1–3 с: утренний экран — один запрос плюс индикатор
  загрузки, план дня — второй запрос в конце.
- Возможно, MS To Do обновляет `createdDateTime` у повторяющихся задач
  при новом экземпляре — тогда они не «застрянут». Не проверено, на
  ритуал не влияет критично.
- Сводка в момент деплоя: рестарт защищён `ritual_runs`, но деплой около
  9:30 и 20:30 лучше не делать.
- Бэкап БД пишется на тот же vps4.

## Решения Александра (2026-10-26)

- Сводки в выходные по умолчанию выключены.
- Вкладка «Входящие» остаётся; убрать — если не будет пользоваться.
- Проекты в ритуал не входят.
- Перенос задачи со временем спрашивает новое время (этап 0).
- Напоминание бота, напоминание MS To Do и событие Google Calendar
  переезжают вместе с задачей на новый день и время (этап 0).
