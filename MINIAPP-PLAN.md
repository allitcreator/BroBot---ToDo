# Мини-апп ToDoBOT — план

Статус: черновик 2026-10-26, до реализации. Прошёл критику `skeptic`,
учтены подтверждённые возражения и ответы Александра.

## Цель

Сценарий, который нужен:

1. Кинуть в чат что угодно — текст, голос, форвард. Без даты это ложится
   во «Входящие» и не засоряет день.
2. Открыть мини-апп и разобрать входящие тапами: на сегодня, на завтра, на
   дату, в проект, закрыть.
3. Там же смотреть «Сегодня / Неделю», проекты, настройки и статистику.

Приложение MS To Do на телефоне почти не открывается, поэтому экраны задач
его не дублируют, а заменяют. Чат остаётся входом для записи, мини-апп —
местом разбора и просмотра.

Решения по `INBOX-CONCEPT.md`, которые из этого следуют:
- главное место разбора — мини-апп; шаг 0 в `/today` и `/inbox` в чате
  не делаем (вопросы 2 и 4 концепта закрыты);
- вход во входящие — правило «нет срока → входящие» (вопрос 1). Нужна дата —
  она пишется в сообщении или комментарием к форварду;
- разобранное-ненужное удаляется насовсем (вопрос 3).

## Не входит

- Разбор текста через LLM и интервью по проекту — остаются в чате.
- Офлайн и локальное зеркало MS To Do. Источник правды — MS To Do.
- Календарь: события Google только отметкой у задачи.

## Замеры (2026-10-26, из прод-контейнера на vps4)

| Запрос | Время |
|---|---|
| Открытые задачи (`status ne 'completed'`, 15 шт.) | 1.0–3.1 с; первый вызов 3.5 с (рефреш токена) |
| Список проектов (0 шт.) | 0.35 с |
| Все задачи списка с пагинацией (1535 шт., 16 страниц) | 27 с |

Выводы:
- Экран задач без кэша будет открываться 1–3 с. Нужен прогрев кэша при
  открытии мини-аппа и показ последнего известного состояния сразу.
- Статистику по завершённым пагинацией не починить: 1520 завершённых — это
  27 с. Нужен `$filter` по `completedDateTime` (проверить, принимает ли Graph)
  или свой счётчик в SQLite по событиям бота.

## Архитектура

Схема splitbot (`../bot_spliwise`), она уже работает на этой машине:

```
Telegram ── https://todo.alxforbot.online
               nginx (vps4)
               ├── /          → /var/www/todobot (статика React)
               └── /api/      → 127.0.0.1:8081/api/  (процесс бота)
```

- **API в процессе бота** — маршруты `/api/*` и `/health` в том же
  `aiohttp.web.Application`. Второй процесс на одном ядре не нужен.
  - Сейчас nginx проксирует `/webhook/todobot/` → `127.0.0.1:8081/` с
    отрезанием префикса, то есть API стал бы доступен и как
    `alxforbot.online/webhook/todobot/api/...`. Поэтому вебхук переносим на
    точный путь (`location = /webhook/todobot/`), второго входа нет.
  - API и вебхук в одном event loop: долгие операции (разведка) не держат
    запрос, а идут фоновой задачей.
- **Авторизация:** `Authorization: tma <initData>`, HMAC по алгоритму Telegram
  (переносим `verify_init_data` из `bot_spliwise/backend/app/api/auth.py` с
  тестами), `user.id == TELEGRAM_USER_ID`, `auth_date` не старше суток. При 401
  фронт показывает «закрой и открой заново», а не пустой экран.
- **Фронт:** React + Vite + TypeScript, без UI-библиотек, тема из
  `Telegram.WebApp.themeParams`, `BackButton`. Сборка локально, на сервер —
  готовая статика (на vps4 одно ядро и VPN-нода).
- **Поддомен `todo.alxforbot.online`:** на `alxforbot.online` стоит
  `X-Frame-Options: DENY`, а Telegram Web открывает мини-апп во фрейме.
  На поддомене — `Content-Security-Policy: frame-ancestors https://web.telegram.org`.
- **Вход:** кнопка меню бота (`setChatMenuButton` с `web_app`) и `/app`.
- **Кэш** живёт в `services/`, а не в слое API: и чат, и мини-апп пишут через
  одни функции, и обе стороны сбрасывают кэш. Правки, сделанные руками в
  приложении To Do, видны не позже TTL (60 с) или по pull-to-refresh.
- **Защита от двойных действий:** кнопка блокируется до ответа, на сервере —
  `asyncio.Lock` на задачу или проект. Запись брифа (`append_to_section`,
  `set_section`) идёт под lock проекта: она читает заметку целиком и пишет
  целиком, параллельная запись иначе теряется.

### API

| Метод | Что делает | Что доделать в `services/` |
|---|---|---|
| `GET /api/projects`, `GET /api/projects/{id}` | список и карточка | `get_project` отдаёт `id` шагов (сейчас выбрасывает, `projects.py:173`) |
| `POST /api/projects/{id}/sections/{name}` | дописать абзац | отказ при `body_valid=False` вместо пересборки шаблоном |
| `PATCH /api/projects/{id}/steps/{item}` | отметить шаг | новая `ms_todo.update_checklist_item` |
| `POST /api/projects/{id}/research` → `GET .../research` | разведка фоном, статус опросом | фоновая задача, таймаут LLM |
| `GET/PATCH /api/settings` | три тумблера | — |
| `GET /api/stats` | счётчики | см. «Замеры» |
| `GET /api/tasks?view=today\|week\|overdue\|inbox` | срезы задач | срез «неделя» (его нет и в чате) |
| `PATCH /api/tasks/{id}` | срок, название, выполнено | `update_task` всегда ставит 20:00 UTC (`ms_todo.py:204`) — сохранять время; чистку календаря и напоминаний (`_cleanup_task_extras`, сейчас в `handlers/callbacks.py:499`) перенести в `services/` и звать при «выполнено» |
| `DELETE /api/tasks/{id}` | удалить | та же чистка |

Ответы — только нужные поля, без сырых объектов Graph. Ошибки — код и
короткий текст для человека, детали в лог.

## Этапы

### Этап A. Минимальный фундамент

Только то, без чего мини-апп сразу сломается или откроет дыру:

1. `.dockerignore` и пересборка (в проде секреты лежат в образе); `127.0.0.1`
   в compose из git.
2. Ежедневный бэкап `bot.db` по cron.
3. `asyncio.Lock` на рефреш токенов MS и Google; ошибка «перевыпусти токен»
   вместо сырого 400.
4. Таймаут (45 с, `max_retries=1`) у LLM-клиента, лог в `classify_message`.
5. Fail-fast на старте: webhook без секрета, пустые обязательные переменные.

Остальное из `AUDIT-2026-10-26.md` (`USER`, ротация логов, healthcheck,
`dp.errors`, тихие `except`) — отдельной задачей, мини-апп от неё не зависит.

Приёмка: тест — два параллельных запроса при протухшем токене дают один
рефреш; тест на fail-fast; `docker run --rm todobot-todobot ls -a /app` не
показывает `.env` и `data/`; после ночи в каталоге бэкапов есть свежий файл.

### Этап B. Входящие: запись в чате, разбор в мини-аппе

Главный сценарий, ради которого всё затевается, поэтому первым.

Бот:
- Убрать автодату в `llm.parse_task` (`services/llm.py:75-77`): нет срока →
  задача без `dueDateTime`. Превью показывает маршрут «📥 Во входящие»,
  рядом кнопка `📅 Сегодня` на случай, если правило ошиблось.
- Форвард без комментария — сразу во входящие, без вопроса «что сделать»
  (заодно уходит баг `/skip` с `saved_forwards`). Форвард с комментарием,
  где есть дата, — задача на эту дату, как сейчас.
- В ответе после записи — счётчик входящих.

Мини-апп (скелет + один экран):
- `miniapp/`, `api/auth.py` с тестами (валидная подпись, чужой `user.id`,
  просроченная, подделанное поле).
- Вебхук на точный путь, nginx-конфиг поддомена в репозитории, certbot,
  `deploy/deploy.sh` по образцу splitbot (`nginx -t` перед подменой, откат).
- Кнопка меню и `/app`.
- Экран «Входящие»: список задач без даты, у каждой — «Сегодня / Завтра /
  Дата / Удалить». Счётчик на вкладке.

Приёмка:
- «купить молоко» без даты попадает во входящие, «завтра в 15 позвонить» —
  на завтра с временем, как раньше;
- мини-апп открывается на телефоне, в Desktop и в Web (проверка фрейма);
- без initData и с чужой подписью — 401;
  `alxforbot.online/webhook/todobot/api/...` — 404;
- разбор элемента виден в `/todotoday` и в MS To Do;
- экран входящих на телефоне открывается быстрее 1.5 с при тёплом кэше;
- двойной тап по «Сегодня» не создаёт двух PATCH.

Метрика из концепта: положено во входящие против разобрано за неделю. Если
склад растёт больше 20 элементов или элементы лежат дольше 14 дней —
разбор неудобен, правим экран, а не терпим.

### Этап C. «Сегодня» и «Неделя»

- «Сегодня»: просроченные блоком сверху, затем сегодняшние; выполнено,
  перенести на завтра / дату, удалить.
- «Неделя»: по дням на 7 дней вперёд (функции среза пока нет нигде).
- Массовый перенос с итогом «перенесено X из Y».
- Перед этим: перенести `_cleanup_task_extras` из `handlers/callbacks.py:499`
  в `services/`, чинить `update_task`, который всегда ставит 20:00 UTC
  (`ms_todo.py:204`).

Приёмка: срезы совпадают с `/todotoday` и `/overdue`; после «выполнено»
событие Google и Telegram-напоминание удалены; перенос даты не сбрасывает
время; правка из чата видна в мини-аппе сразу, из To Do — не позже 60 с.

### Этап D. Проекты, настройки, статистика

- Проекты: список, карточка с брифом и шагами, отметка шагов, «Дополнить
  секцию», «Разведать» фоном со статусом. Lock на проект, блокировка кнопок.
- Из входящих — кнопка «В проект»: дописать элемент в секцию существующего
  проекта или запустить интервью в чате.
- Настройки: три тумблера.
- Статистика: подсчёт завершённых через фильтр по дате или свой счётчик.

Приёмка: дописанная секция видна в `/projects` и в To Do, вложение
`brief.md` одно после «Дополнить» и «Разведать» подряд; разведка дольше
60 с не даёт 504; при выключенных проектах вкладки нет, API отвечает 403;
тумблер в мини-аппе меняет `/settings` в чате; `/stats` и экран совпадают
и считаются быстрее 3 с.

## Проверки на всём пути

- `venv/bin/python -m pytest tests -q`, включая тесты API на aiohttp test client.
- `npm run typecheck && npm test` в `miniapp/`.
- Живой прогон на телефоне после каждого этапа: бот один, в проде.

## Риски

- **Задержки Graph 1–3 с** на срез задач. Если тёплый кэш не спасает —
  показывать последнее известное состояние сразу и обновлять фоном; локальное
  зеркало — только если и это не поможет.
- **Склад превратится в свалку** — главный риск концепта входящих. Отсюда
  метрика в Этапе B.
- **Протухание токенов** станет заметнее: мини-апп ходит в Graph чаще.
- **Общий процесс:** падение API валит вебхук. Тесты API обязательны,
  тяжёлое — в фоне.
- **vps4 совмещённая** с LV-выходом VPN: nginx и certbot только через
  `nginx -t`, с бэкапом конфига.

## Что изменилось после критики и ответов

- Порядок: был «фундамент → входящие в чате → скелет → задачи → проекты»,
  стал «фундамент → входящие (чат + мини-апп) → сегодня/неделя → проекты».
  Входящие — главный сценарий, проверяется первым.
- `/inbox` в чате и шаг 0 в `/today` убраны: место разбора одно.
- Добавлено: чистка календаря при «выполнено», сохранение времени при
  переносе, lock на запись брифа, фоновая разведка, закрытие второго входа
  через `/webhook/todobot/api`, экран на просроченный initData, пороги
  скорости в приёмке, метрика «положено против разобрано».
- Цифра «Graph отвечает за 0.3–1 с» заменена замером.
- A-запись `todo.alxforbot.online` заведена в reg.ru 2026-10-26; на момент
  записи авторитетный `ns1.reg.ru` её ещё не отдавал — проверить перед Этапом B.
