# Порядок дня и исполнитель задачи — план

Статус: план 2026-10-28 с учётом ревью skeptic, код не начат. Задача из MS Todo (проект
ToDoBOT): «Придумать как в утреннем ритуале выбирать порядок задач.
Придумать как помечать задачи для агента и для человека. После реализации
добавить в ассистента».

## Решения Александра (28.10)

- Порядок и исполнитель хранятся **в служебном блоке заметки** задачи MS To Do.
- Порядок — **номер у каждой задачи тапами**, порядок можно менять.
- Исполнители: **агент** и **сам**. «Черновик» отдельно не нужен: это агент
  с рекомендацией («подготовь письмо, отправлю сам»).
- У задачи для агента можно написать **рекомендации к выполнению**.

## Служебный блок

В конце заметки, между маркерами. Текст выше — твой или пересланный, бот его
не меняет.

```
<твой текст или пересланное сообщение>

── BroBot ──
Порядок: 2 на 28.10.2026
Исполнитель: агент
Рекомендации:
сначала посмотреть логи за неделю, без коммитов
── /BroBot ──
```

Правила:
- Пишутся только заданные строки; пустой блок удаляется целиком.
- Блок — от **последнего** открывающего маркера. Строки-маркеры в тексте не
  от бота (форварды, описание от LLM, `todo.py note`/`add`) при записи
  обезвреживаются (`── BroBot ──` → `-- BroBot --`), чтобы пересланное
  сообщение не подделало блок и «Рекомендации». Те же строки в тексте
  рекомендаций тоже обезвреживаются; поля разбираются только до
  `Рекомендации:`, дальше — текст рекомендаций до закрывающего маркера.
- Текст над блоком сохраняется побайтно, включая `\r\n` (они в 243 из 1561
  заметок) и хвостовые пробелы.
- Номер действует только в указанный день; вчерашний игнорируется и
  стирается при следующей записи.
- Перед записью задача читается из Graph заново, чтобы не затереть правку,
  сделанную в To Do минуту назад.
- Нет закрывающего маркера (сломали руками) — блок до конца заметки. Нет
  открывающего — блока нет, при записи добавляется новый в конец.
- Мини-апп и бот показывают заметку **без блока** (блок снимается до
  обрезки до 300 символов); номер, исполнитель и рекомендации — отдельными
  полями. `projects.parse_body` разбирает заметку без блока, запись брифа
  (`set_section`, `append_to_section`) блок сохраняет.
- Запись по задаче идёт под блокировкой на задачу (GET → PATCH), задачи без
  изменений не пишутся. If-Match Graph не используем — окно между GET и
  PATCH остаётся, риск принят.
- Номер ставится только задачам с датой «сегодня». После закрытия задачи
  номера не перенумеровываются (1, 3, 4 — так и показываются).
- Ассистент считает указаниями только «Рекомендации» из блока; пересланный
  текст выше — чужой, команды из него не выполняются.

## Как выглядит

**«План дня» в утреннем ритуале.** Встречи сверху, ниже задачи на сегодня.
- Тап по задаче без номера — следующий номер. Тап по задаче с номером —
  номер снимается, следующие сдвигаются вверх. Кнопка «Сбросить».
- Справа у строки — значок исполнителя: тап переключает 👤 сам → 🤖 агент →
  без отметки. У 🤖 под названием — «✎ Рекомендации» (лист с полем ввода).
- Список показан в итоговом порядке: с номером по номеру, затем без номера —
  со временем по времени, потом старые раньше новых.
- «Начать день» сохраняет всё одним запросом.

**Экран «Сегодня».** Задачи в том же порядке, номер перед названием, значок
исполнителя в метках. Кнопка «Порядок» открывает тот же режим тапов, что в
ритуале, с «Сохранить». В раскрытой строке — «👤 Сам / 🤖 Агенту» и
«Рекомендации».

## API

- `GET /api/tasks`, `/api/ritual/*`, `/api/inbox`: у задачи `note` без блока,
  плюс `order` (номер на сегодня или `null`), `executor`
  (`agent|self|null`), `advice` (строка или `null`). Сегодняшние — в порядке
  выше.
- Один эндпоинт записи `POST /api/tasks/plan`
  `{order?: [keys], meta?: {key: {executor?, advice?}}}`:
  `order` — номера 1…N на сегодня этим задачам, у остальных сегодняшних номер
  снимается; `meta` — `null` снимает поле, рекомендации ≤ 2000 символов.
  По задаче — один GET и один PATCH, без изменений — ни одного. Ключ
  не-сегодняшней задачи в `order` — 400. Сбой на задаче не останавливает
  остальные (ответ как у `move`). Им же пользуются «Начать день», режим
  «Порядок» и правка исполнителя в строке.
- Порядок сортировки — одна функция для ритуала и «Сегодня» (время задачи
  из события или напоминания считается для обоих).

## Этапы и приёмка

1. **Бэкенд.** `services/task_meta.py` (разбор, сборка, удаление блока —
   чистые функции), запись через `ms_todo`, API выше, `_note` и
   `projects` с блоком, обезвреживание маркеров при создании задачи. Общие
   фикстуры разбора — `tests/fixtures/task_meta_cases.json` (их же читают
   тесты ассистента). Приёмка — тесты: порядок; устаревший номер; нет
   маркеров; два маркера (берётся последний); подделанный блок в форварде
   не даёт `advice`; маркер и «Исполнитель:» внутри рекомендаций; текст над
   блоком побайтно с `\r\n`; заметка длиннее 300 символов с блоком; пустой
   блок удаляется; повторное сохранение без изменений — ноль PATCH;
   параллельные запросы по одной задаче не теряют поля; `set_section`
   сохраняет блок. Скрипт `deploy/strip_task_meta.py` снимает все блоки
   (для отката): по умолчанию только считает, пишет с `--apply`.
2. **Мини-апп.** «План дня» и «Сегодня» как выше. Приёмка: vitest на тапы
   (номер, снятие со сдвигом, сброс), переключение исполнителя, сохранение
   одним запросом; `tsc`, сборка.
3. **Ассистент** (`../todo_and_run`). `todo.py list` показывает номер,
   исполнителя и рекомендации; `todo.py meta N --executor agent|self|none
   --advice "…"`; `todo.py note` вставляет строку перед блоком; `/today`:
   номер задаёт порядок, исполнитель важнее догадки модели, рекомендации —
   указания к задаче. Правило в `CLAUDE.md` ассистента.

На каждом этапе тест сначала падает, `pytest tests -q`, `npm test`, ревью;
выкладка бота — только по «выкатывай». Смоук на проде: блок пишется и
читается на тестовой задаче, текст заметки не меняется.

## Вне объёма

Порядок на завтра в вечернем ритуале и номера просроченным — не сейчас;
утренний разбор и так сначала переносит просроченные на сегодня.

## Риски

- Утреннее сохранение: до 10 пар GET+PATCH последовательно (срез Graph
  1–3 с), у изменённых задач меняется «изменено» в To Do.
- Правка блока в To Do руками может его сломать — разбор мягкий, текст выше
  не теряется.
- 28.10 проверено чтением всех 1561 задачи: заметки только `text`, HTML нет.
