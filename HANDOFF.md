## Цель

Научить ToDoBOT различать на входе напоминание и идею проекта. Напоминание —
текущий флоу без изменений. Проект — интервью с челленджем, на выходе бриф и
план шагов, всё складывается задачей в список «Проекты» в MS To Do.

Контракт и обоснования решений — в `PROJECTS-CONCEPT.md`.

Сессия 2026-09-08 добавила к этому выключатель фичи проектов в `/settings`
(задача «Фичу про проекты вынести в настройки и сделать отключаемой»).

продукт для других. Для личной не спрашивает «кто просил» и про деньги, а давит
на «как часто реально сталкиваешься», «чем не устраивает готовое», «будешь ли
пользоваться через месяц». Probe про затраты работает всегда. Глубина под
масштаб: мелкая затея — 4-6 вопросов. Дословный повтор вопроса запрещён.

## Решения и ограничения

- **Источник правды — MS To Do.** Бриф в `body.content` фиксированными
  markdown-секциями, шаги в `checklistItems`, MD-файл вложением. Локального
  зеркала нет: чтобы дополнить секцию, бот читает свой же текст обратно.
- Вложение не обновляется — `replace_attachment` сносит одноимённое и создаёт
  заново; проверено, дублей не остаётся.
- Решение «это проект» принимается до создания задачи: перенос между списками
  в Graph невозможен.
- Классификация — отдельный LLM-вызов на каждое входящее сообщение. Это плюс
  задержка примерно в один вызов; сознательный размен на точность.
- Форварды идут по старому пути, как задачи. Форвард-как-проект — открытый
  вопрос №3 в концепте, в MVP не делали.
- Состояния бота single-slot (как `pending_task`): если поверх `unclear`
  прилетело новое сообщение, тап по старой кнопке отвечает «сообщение
  устарело», а не создаёт задачу не из того текста.
- Локальный `venv/` пересобран 2026-09-08 на Python 3.12 (`~/.local/bin/python3.12`):
  прежний был битый, homebrew снёс из-под него python@3.13, и pytest внутри не
  стоял. Теперь работает штатное `venv/bin/python -m pytest tests -q`.
  `venv/` в `.gitignore`, на репозиторий это не влияет.
- Выключатель проектов проверяется в трёх местах, а не в одном: у фичи три
  входа, и два из них (кнопка в истории чата, прямая команда) переживают
  выключение. Один флаг на отрисовку клавиатуры этого не закрывает.

## Выбор модели

Проверены шесть моделей OpenRouter на реальных сценариях интервью.
`qwen3.5-flash`, `deepseek-v4-flash`, `glm-4.7-flash` (самые дешёвые с
заявленным `response_format`) отпали: возвращают текст вместо JSON или упираются
в лимит reasoning-токенов. `gpt-5-mini` даёт хорошие вопросы, но 8-12 секунд на
ход и 500-800 reasoning-токенов — дороже и медленнее. `gemini-2.5-flash` быстрее
и дешевле, но мягче в челлендже.

Остаётся `google/gemini-3-flash-preview`: 1.4-2.3 с на ход, валидный JSON 3/3,
самое жёсткое давление в probe. Цена интервью — около 1.5 цента, при четырёх
проектах в месяц это 6 центов; экономить тут не на чем.

   - README обещает команду `/week`, которой нет.
4. **Этап 1 — входящие** по готовому `INBOX-CONCEPT.md`. Фундамент частично

## Rollback

Выключатель проектов (сессия 2026-09-08, уже в проде):

```
git revert 424f59a && git push origin main
# на vps4:
cd /root/todobot && git pull && docker compose up -d --build
```

Колонку `projects_enabled` откатывать не нужно: миграция только добавляет её,
старый код на неё не смотрит. Бэкап БД перед выкаткой —
`vps4:/root/todobot/data/bot.db.bak-20260908`.

Быстрее ревёрта: саму фичу проектов можно выключить прямо в `/settings`, для
этого тумблер и делался.

Прод (прошлая сессия): на VPS `git reset --hard 105c929 && docker compose up -d --build`.
БД откатывать не нужно — миграция только добавила колонку, но бэкап лежит
рядом (`data/bot.db.bak-20260824`), `.env` тоже (`.env.bak-20260824`).

Репозиторий: `git revert a4b7577` вернёт проекты, не трогая фикс напоминания.

приложении или `DELETE /me/todo/lists/{MS_PROJECTS_LIST_ID}`.
